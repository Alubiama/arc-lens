Why two event streams are not two payments

Arc emits USDC system events from the system emitter, and can also carry ERC-20 Transfer logs from the USDC token contract. These two streams can describe the same underlying movement twice, in two encodings. Arc Lens counts only the verified system-emitter transfers as canonical movements, and treats the ERC-20 logs as alternative supporting evidence — never as extra movements, and never by summing both or by pairing logs that merely share an amount. Same-amount transfers that are genuinely distinct stay distinct because each carries its own log index.

When a receipt carries ERC-20 transfer logs but no verified system transfers, Arc Lens flags the event evidence as incomplete instead of inventing a movement. A reverted transaction moves no funds, though its fee is still charged.

About this tool

  • Arc Lens performs no signing, holds no wallet, and runs no server.
  • It collects no private data; the only input it needs is a transaction hash.
  • It explains USDC events, not other tokens, trade outcomes or a wallet’s full balance history.
  • Numbers come straight from the receipt; fee and amounts are explained separately.
